# Reconciliation AI — Инструкция по локальному Docker-контейнеру

Документ описывает, как собрать самодостаточный Docker-образ приложения и как
им пользоваться: локально, на другой машине (в том числе офлайн) и с GPU.

---

## 0. Что это за образ

**`recon-ai:local`** — один контейнер, внутри которого работают три процесса
(через supervisord):

| Процесс  | Порт  | Назначение                                             |
|----------|-------|--------------------------------------------------------|
| Ollama   | 11434 | Локальная LLM. Модель **запечена в образ**              |
| Backend  | 5057  | Fastify API: парсинг PDF/Excel, OCR, маппинг, сверка    |
| Frontend | 5173  | Веб-интерфейс (Vite), проксирует `/api` на backend      |

Особенности:

- **Секретов в образе нет.** Приложение работает в режиме `REQUIRE_LOCAL_ONLY=true`:
  никакие облачные API (OpenRouter и т.п.) не вызываются вообще. Файл `.env` не нужен.
- **Интернет при запуске не нужен.** Модель `qwen2.5:7b-instruct` (~4.7 ГБ)
  скачивается один раз *при сборке* и хранится внутри образа.
- Работает на **CPU** (медленнее) и на **NVIDIA GPU** (быстро) — без пересборки,
  только флагом запуска.

---

## 1. Требования для сборки образа

- Установленный Docker (Docker Engine 24+ или Docker Desktop).
- Машина с интернетом (для сборки).
- Свободное место на диске: **~20–25 ГБ** (зависимости + модель + слои образа).
- Оперативная память: **не менее 8 ГБ** (лучше 16 ГБ).
- Архитектура CPU: образ собирается под архитектуру вашей машины
  (`amd64` для Intel/AMD, `arm64` для Apple Silicon / ARM-серверов).
  ⚠️ Переносить образ можно только между машинами **одной архитектуры**
  (или собрать multi-arch — см. раздел 6).

Проверка Docker:

```bash
docker --version
docker info | grep -i arch
```

---

## 2. Сборка образа

```bash
# 1. Клонируем ветку с улучшениями
git clone -b feature/ai-improvements https://github.com/Yogurt7v/ReconciliationAI.git
cd ReconciliationAI

# 2. Собираем образ (долгий шаг: ~15–40 минут, скачивает модель ~4.7 ГБ)
docker build -f Dockerfile.allinone -t recon-ai:local .
```

Готово. Проверка:

```bash
docker images | grep recon-ai
# recon-ai   local   xxxx   X minutes ago   ~12 GB
```

### Смена модели

Если хотите другую модель (например, `qwen2.5:3b-instruct` для слабых машин):

1. Откройте `Dockerfile.allinone`.
2. Замените в **двух местах**:
   - `ENV ... OLLAMA_MODEL=qwen2.5:7b-instruct`
   - строку `ollama pull qwen2.5:7b-instruct`
3. Пересоберите образ.

Требования к модели: поддержка строгого JSON-вывода, контекст ≥ 4096 токенов,
русский + английский языки, стабильность при низкой температуре.

## 3. Первый запуск (на этой же машине)

```bash
docker run -d \
  --name recon-ai \
  -p 5173:5173 \
  -p 5057:5057 \
  recon-ai:local
```

Подождите 20–60 секунд (Ollama должна поднять модель в память), затем:

- **Откройте в браузере:** http://localhost:5173
- Backend API напрямую (опционально): http://localhost:5057

Проверка здоровья:

```bash
# Все три процесса должны быть RUNNING
docker exec recon-ai supervisorctl status

# Ollama жива и модель на месте
docker exec recon-ai curl -s http://127.0.0.1:11434/api/tags | head -c 300

# Логи приложения
docker logs -f recon-ai
```

### Быстрый старт с GPU (если есть NVIDIA)

Никакой пересборки не нужно — просто добавьте флаг:

```bash
docker rm -f recon-ai
docker run -d \
  --name recon-ai \
  --gpus=all \
  -p 5173:5173 \
  -p 5057:5057 \
  recon-ai:local
```

Условия: установленные драйверы NVIDIA + NVIDIA Container Toolkit на хосте.
Без GPU контейнер автоматически работает на CPU.

### Полезные команды

```bash
docker stop recon-ai            # остановить
docker start recon-ai           # запустить снова (без пересборки)
docker restart recon-ai         # перезагрузить
docker logs --tail 100 recon-ai # последние строки лога
docker rm -f recon-ai           # удалить контейнер (образ остаётся)
```

Данные загруженных документов и отчёты живут внутри контейнера. Если хотите
сохранять их между удалениями контейнера — добавьте volume:

```bash
docker run -d --name recon-ai -p 5173:5173 -p 5057:5057 \
  -v recon-uploads:/app/backend/uploads \
  -v recon-reports:/app/backend/reports \
  recon-ai:local
```

## 4. Как пользоваться приложением

1. Откройте **http://localhost:5173**.
2. Выберите режим:
   - **Анализ одного файла** — загрузите PDF (текстовый или скан) или XLSX.
   - **Сравнение двух файлов** — загрузите ровно 2 файла (акт ↔ акт,
     выгрузка ↔ реестр и т.п.).
3. Нажмите «Распознать» / «Сравнить».
4. Дождитесь результата:
   - **Таблица результатов** — извлечённые поля (номер, дата, сумма, дебет/кредит).
     Ячейки с низкой уверенностью подсвечены красным.
   - **«Логика AI»** — раскрывающийся лог всех этапов: качество скана, OCR,
     маппинг колонок, self-consistency check.
5. Кнопка **«Экспорт»** — скачать результат в Excel/HTML.

Важно: в текущей сборке включён режим *только локальной модели*. В окне
«Настройки AI» будут доступны лишь локальные модели Ollama; облачные провайдеры
жёстко отключены на уровне бэкенда. Никаких API-ключей вводить не нужно.

## 5. Перенос образа на другую (более мощную) машину

### 5.1 Экспорт (на машине, где собран образ)

```bash
docker save recon-ai:local | gzip > recon-ai-local.tar.gz
```

Размер архива ≈ размер образа (~10–15 ГБ). Имя файла — любое на ваш вкус,
`recon-ai-local` = «Reconciliation AI, локальный режим», `.tar.gz` — стандартный
формат docker save.

### 5.2 Перенос

Скопируйте архив любым способом: флешка, `scp`, внутренний сетевой диск:

```bash
scp recon-ai-local.tar.gz user@target-host:/data/
```

### 5.3 Импорт и запуск на целевой машине

```bash
# Интернет НЕ требуется
gunzip -c /data/recon-ai-local.tar.gz | docker load

# Запуск (CPU):
docker run -d --name recon-ai -p 5173:5173 -p 5057:5057 recon-ai:local

# Запуск (NVIDIA GPU — рекомендуется на мощной машине):
docker run -d --name recon-ai --gpus=all -p 5173:5173 -p 5057:5057 recon-ai:local
```

Откройте http://localhost:5173 на целевой машине — всё то же самое, модель уже внутри.

⚠️ Ещё раз про архитектуру: `amd64`-образ не запустится нормально на `arm64`
(и наоборот). Проверьте целевую машину: `uname -m` → `x86_64` = amd64,
`aarch64`/`arm64` = arm64.

## 6. Альтернатива: публикация в реестр (без tar-архива)

Если у обеих машин есть интернет, удобнее гонять образ через реестр:

```bash
docker tag recon-ai:local ghcr.io/<ваш-логин>/recon-ai:local
docker push ghcr.io/<ваш-логин>/recon-ai:local
# На целевой машине:
docker pull ghcr.io/<ваш-логин>/recon-ai:local
```

Multi-arch сборка (если целевая машина другой архитектуры):

```bash
docker buildx build -f Dockerfile.allinone \
  --platform linux/amd64,linux/arm64 \
  -t ghcr.io/<логин>/recon-ai:local --push .
```

## 7. Варианты запуска (шпаргалка)

Кроме all-in-one образа в репозитории есть два compose-варианта:

| Вариант | Команда | Когда использовать |
|---------|---------|--------------------|
| **C. All-in-one** (эта инструкция) | `docker build -f Dockerfile.allinone -t recon-ai:local .` | Полный офлайн, перенос на другие машины |
| B. Compose + отдельный Ollama | `docker compose --profile with-ollama up -d --build` + `docker compose exec ollama ollama pull qwen2.5:7b-instruct` | Разработка, модель в volume, быстрее пересборка |
| A. Ollama уже стоит на хосте | `AI_PROVIDER=ollama docker compose up backend frontend` (в `.env`: `OLLAMA_BASE_URL=http://host.docker.internal:11434`) | Не дублировать Ollama |

## 8. Частые проблемы (FAQ)

**1. Страница открывается, но анализ падает с ошибкой «Ollama недоступна».**
Модель ещё грузится в память (первый запрос после старта медленный, 30–120 с
на CPU). Проверьте:
```bash
docker exec recon-ai curl -s http://127.0.0.1:11434/api/tags
```
Если ответа нет — смотрите `docker logs recon-ai` и статус `supervisorctl status`.

**2. `docker: Error response from daemon: could not select device driver "nvidia"`.**
Не установлен NVIDIA Container Toolkit. Либо уберите `--gpus=all` — приложение
работает на CPU.

**3. Контейнер убит (exit code 137).**
Не хватило RAM под модель 7B. Решения: увеличить память Docker, либо пересобрать
образ с моделью `qwen2.5:3b-instruct` (см. раздел 2).

**4. Очень медленно на CPU.**
Нормально для 7B на CPU. На «более мощной машине» с видеокартой NVIDIA просто
добавьте `--gpus=all` — скорость вырастет в разы без пересборки.

**5. Ошибка «no matching manifest for linux/arm64» при docker load/run.**
Образ собран под другую архитектуру. Пересоберите его на машине целевой
архитектуры или используйте multi-arch push (раздел 6).

**6. Нужно поменять модель/поведение без пересборки.**
Часть параметров переопределяется при запуске ENV-флагами, например:
```bash
docker run -d --name recon-ai -p 5173:5173 \
  -e OLLAMA_MODEL=qwen2.5:7b-instruct \
  recon-ai:local
```
Но сама модель должна присутствовать в образе (иначе её нечем отвечать —
интернета в контейнере может не быть).

## 9. Безопасность

- В образе **нет секретов**: никаких API-ключей, токенов и паролей.
- Режим `REQUIRE_LOCAL_ONLY=true` гарантирует, что данные документов
  **никуда не уходят** — весь разбор происходит внутри контейнера.
- Порты (5173/5057) публикуйте наружу только при необходимости; для локального
  использования достаточно localhost.
- При переносе `tar.gz` учитывайте: файл содержит исходники и модель — ведите
  себя с ним как с кодом репозитория.
